# Invoice follow-up screen

Synthetic planning fixture, not a running application.

The audience is a freelancer checking which customers need a payment reminder.
They know their customers but need to see which invoices are overdue, how much
is owed, and whether a reminder was recently sent. They usually have 20–80
invoices and work primarily on a laptop, occasionally on a phone.

The screen must include the existing invoice table with customer, invoice
number, due date, outstanding amount, status, and last reminder date. Preserve
access to all invoices. Read `components.md` for optional candidates and the
available data and actions. Use the current restrained design conventions.

Deliver a plan describing hierarchy, component choices, and how a person finds
an overdue invoice, sends a reminder, and sees the outcome. Account for a new
account with no invoices, no results after filtering, and failed data loading
or reminder sending. Keep this task to planning; leave all fixture files intact.
